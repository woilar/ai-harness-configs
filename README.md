# AI Toolkit

Личный набор AI-инструментов: фреймворк работы и обучения на Java, настройки, навыки и плагины.
Конфигурации инструментов находятся в `tools/`; фреймворк — в `framework/`, самостоятельные навыки — в `skills/`, плагины — в `plugins/`. У компонентов собственные инструкции установки.

| Harness | Состояние | Настройка |
| --- | --- | --- |
| Oh My Pi | Готовая конфигурация: Copilot, Coach, Executor | [tools/omp/README.md](tools/omp/README.md) |
| OpenCode V2 | Те же роли и общие правила, отдельная установка | [tools/opencode/README.md](tools/opencode/README.md) |
| Codex | Те же роли и общие правила для локального Codex | [tools/codex/README.md](tools/codex/README.md) |
| DeepSeek Harness | Место для будущей конфигурации | [tools/deepseek-harness/README.md](tools/deepseek-harness/README.md) |


## Плагины и навыки

- [OpenCode Review](plugins/opencode-review/README.md): комментарии у кода, обсуждения и отправка новых сообщений из IDEA в текущую сессию OpenCode. Обе части плагина, тесты и общий установщик находятся рядом.
- [Самостоятельные навыки](skills/README.md): место для независимых skills. Роли фреймворка остаются в `framework/agent/skills/`.

Готовые комплекты плагинов публикуются в [GitHub Releases](https://github.com/woilar/ai-harness-configs/releases). В Git хранятся исходники, тесты и скрипты сборки.

## Совместимость после переноса

Файлы фреймворка сохранены целиком. Старые пути `shared/agent`, `omp`, `codex`, `opencode`, `deepseek-harness` и `evals` остаются относительными ссылками на новую структуру. Прежние команды установки продолжают работать; существующие глобальные ссылки и записи OpenCode по пути `shared/agent` остаются действительными. Установщики намеренно используют этот стабильный путь.

Переносить сам checkout после установки по-прежнему нужно с повторной установкой: глобальные ссылки содержат абсолютный путь. На Windows клонирование должно сохранять символические ссылки (Developer Mode/права на создание ссылок); установщики фреймворка рассчитаны на Mac/Linux.

## Начать после распаковки

Из папки `ai-harness-configs` на Mac/Linux:

```bash
bash tools/omp/scripts/install.sh --dry-run
bash tools/omp/scripts/install.sh
```

При установке, повторном запуске и `--dry-run` выводится наличие Plannotator
в PATH и ссылка на его официальный GitHub при отсутствии CLI. Проверка ничего
не устанавливает и не блокирует обновление правил. Запуск и доступность из
процесса BB/агента проверяются отдельно.

Установщик подключает маршрутизатор, модули правил и роли из `framework/agent/` к стандартному глобальному
каталогу `~/.omp/agent/`. Существующие другие настройки сохраняются.
При конфликте он останавливается до изменений; порядок объединения описан
в [инструкции OMP](omp/README.md).

[Гайд](docs/engineering-ai-skills-guide.md) объясняет режимы и ссылается на
актуальные исходники без дублирования установочных текстов. Шаблон договорённостей уже включён в общую политику.

## Режимы

- **Copilot:** основной напарник — исследует факты, задаёт вопросы, помогает
  сформулировать собственный план. Рабочий код не пишет.
- **Coach:** учит недостающей основе через объяснения и практику. Явный Coach
  сохраняет обучение даже для маленькой задачи.
- **Executor:** выполняет понятный согласованный микрошаг, проверяет его и
  запрашивает самостоятельное объяснение diff.

## Хранить в GitHub и обновлять

Создайте свой репозиторий и загрузите содержимое этой папки, включая `.gitignore`.
Служебная папка `.git` в архив не включена; новую историю создаёт владелец.
После клонирования установка выполняется той же командой выше.

При обновлении клонированного репозитория:

```bash
git pull
```

Символические ссылки продолжают указывать на обновлённые файлы. Затем запустите
новую сессию OMP. Если переместили репозиторий, нужно исправить прежние ссылки;
установщик покажет их как конфликт.

## Изменять настройки и добавлять другой harness

Общие тексты фреймворка находятся в `framework/agent/`; `tools/omp/agent` — ссылка для
совместимости с прежними установками. Гайд содержит
ссылки на эти исходники; загрузка справочников остаётся ленивой.
Общие правила ролей хранятся в `framework/agent/role-orchestration.md`;
`framework/agent/AGENTS.md` — совместимая ссылка на этот файл.
В стартовом контексте — только маршрутизатор. Он определяет процесс по смыслу
запроса и готовности задачи, затем требует прочитать соответствующий модуль из
`references/` до действия. `policy-details.md` — короткий индекс совместимости;
установщики проверяют и подключают файлы из `reference-files.txt`, не загружая
их содержимое в стартовые инструкции. Изменения правил доступны через ссылки;
после обновления запустите установщик для подключения новых файлов (в Codex он
также обновляет управляемый блок маршрутизатора).
Новый harness получает папку в `tools/` со своим README, конфигурацией и установщиком.

Конфиги удобно хранить в `~/ai/ai-harness-configs/`, личное учебное хранилище —
в `~/ai/learning/` рядом с репозиторием, но вне него.
План, договорённости, прогресс и точка продолжения хранятся в
`.ai-plans/<task-id>/plan.md` внутри worktree; случайные находки — в
`.ai-plans/findings.md`. Документы исключаются из Git локально. Содержательный
черновик автоматически отправляется MD-вложением через встроенный `plannotator_inbox`.
Одна задача — один тред; новые редакции решения прикладываются туда же, прогресс
не пересылается. Локальный `inbox.json` хранит тред, сообщения, редакции и хеши;
источник истины — исходный MD. Замечания и явное утверждение привязаны к редакции.
Реализация требует отдельного запроса. При ошибке локальный план сохраняется,
доставка не объявляется успешной. Протокол — [plan-inbox.md](framework/agent/references/plan-inbox.md).
Если пользователь явно откладывает исправление находки или связанное решение,
агент сразу отправляет безопасную сводку в Plannotator Inbox. Сообщение остаётся
там после удаления worktree; к уведомлению о находке план и рабочие файлы не прикладываются.
Ключ, статус и подтверждение доставки сохраняются в записи находки. Недоступный
Inbox не мешает текущей работе: агент явно сообщает о неотправленном уведомлении.
Известная текущая задача восстанавливается автоматически перед продолжением
после compaction/смены модели; выбор задачи в новой сессии и обзор остальных
планов — по запросу. Примеры — в
[гайде](docs/engineering-ai-skills-guide.md#планы-и-прогресс-в-worktree). Карточки выявленных пробелов
хранятся отдельно в `~/ai/learning/gaps/`; после отложенной самостоятельной
проверки на изменённой задаче — в `~/ai/learning/archive/`. Короткий
`~/ai/learning/index.md` позволяет выбрать тему без чтения всего журнала. Каждая карточка автоматически содержит текстовый указатель проекта/файла/метода/строк
и независимый выдуманный пример с кодом и условиями упражнения.
Рабочий код, diff, конфигурация и логи не копируются; ссылки не создаются.
Coach в доступном указанном проекте разбирает актуальное место,
а без доступа использует выдуманный пример. Coach читает их
по просьбе «разберём мои пробелы» или «давай позанимаемся»: сначала индекс,
затем одну выбранную карточку. Установщик подключает правила, но не переносит
старые журналы; перенос выполняется отдельно при доступе к исходным файлам.
Общие правила находятся в этом репозитории; личные карточки сюда не публикуются.

## Проверить установщик

Для тестов нужен Python 3; для самой установки достаточно Bash и стандартных
утилит Mac/Linux:

```bash
bash scripts/test-framework.sh
```

Тесты используют временные целевые папки и не меняют глобальную конфигурацию.
