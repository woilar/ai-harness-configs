# Oh My Pi: глобальная конфигурация

Комплект работает на Mac/Linux. Oh My Pi устанавливается отдельно;
скрипт подключает только инструкции и skills. Для установки нужны Bash,
`ln`, `mkdir`, `readlink`, `rm` и `dirname`.

## Стандартный профиль

Из корня репозитория:

```bash
bash tools/omp/scripts/install.sh --dry-run
bash tools/omp/scripts/install.sh
```

По умолчанию цель — `~/.omp/agent/`. Скрипт проверяет источники и все конфликты
до записи. Он создаёт ссылки на `AGENTS.md`, модули `references/*.md` из `reference-files.txt`
и папки `skills/copilot`, `skills/coach`, `skills/executor`.
Правильные существующие ссылки пропускаются; повторный запуск не меняет их.
Если создание новой ссылки не удалось, созданные этим запуском ссылки убираются;
созданные пустые папки могут остаться.

## Именованный профиль и свой каталог

```bash
bash tools/omp/scripts/install.sh --profile java
```

Цель — `~/.omp/profiles/java/agent/`. Используйте этот вариант для профиля,
в котором запускаете OMP. `--profile default` выбирает стандартный профиль.
Имена профилей поддерживают латинские буквы, цифры, `_` и `-`.

Для собственного размещения, включая XDG или перенесённый agent-каталог:

```bash
bash tools/omp/scripts/install.sh --target /absolute/path/to/agent
```

`--profile` и `--target` нельзя объединять. Целевой путь должен быть абсолютным.
Скрипт не определяет активный профиль по `OMP_PROFILE` и не угадывает
`PI_CONFIG_DIR`, `PI_CODING_AGENT_DIR` или XDG-размещение; цель выбирается явно.
`--dry-run` можно добавить к любому варианту; `--help` показывает параметры.

## Если настройки уже есть

Скрипт выведет все конфликтующие пути и ничего не установит.

1. Сравните существующий `AGENTS.md` с `shared/agent/role-orchestration.md` в корне репозитория.
2. Добавьте свои полезные инструкции в исходник репозитория, заменив только
   прежние правила этих трёх режимов. Персональные изменения в публичном
   репозитории делайте осознанно.
3. Сохраните конфликтующие прежние файлы или папки в резервное место вне
   каталогов обнаружения skills; затем освободите только показанные пути.
4. Снова выполните установщик.

Автоматического перезаписывания, удаления существующих конфигураций и
изменения остальных настроек нет. Ссылка на другую копию этого репозитория
тоже считается конфликтом.

## Использовать режимы

После установки запустите новую сессию OMP из рабочего проекта.
При включённом `skills.enableSkillCommands` доступны:

```text
/skill:copilot <задача, моя гипотеза и сомнение>
/skill:coach <непонятная задача или тема>
/skill:executor <точная понятная правка или согласованный шаг>
```

Если команды отключены, включите `skills.enableSkillCommands` в настройках OMP
или попросите агент использовать skill по имени. Copilot — основной режим;
план формулируете вы. Отсутствие основы переводит работу в Coach.

`/strict` и `/deferred` — текстовые инструкции поведения из AGENTS.md,
не зарегистрированные установщиком команды приложения. Их можно писать
в обычном сообщении: «Применяй /strict к этой задаче».
Явный Coach уже сохраняет учебный формат без отдельного `/strict`.

## Что читает агент

- `AGENTS.md`: короткий глобальный маршрутизатор.
- `skills/<роль>/SKILL.md`: тактика только активной роли.
- `references/policy-details.md`: короткий индекс для совместимости старых ссылок.
- Нужный `references/*.md`: обязательно до действия по событию, указанному в
  маршрутизаторе; planning — для новой работы без согласованного решения,
  task-state — до записи рабочего состояния, execution — до исполнения, validation — до
  проверок, handoff — при восстановлении/смене роли, learning-journal — при пробеле.
- `skills/<роль>/references/java-impact-checklist.md`: только Diff Review
  после кодинга, по релевантности.
- `skills/coach/references/scientific-basis.md`: научная основа метода.

Гайд остаётся человеческой документацией; целиком загружать его не нужно.
Для нетривиального планирования агент ведёт MD в `.ai-plans/<task-id>/plan.md`
текущего worktree. Содержательный черновик автоматически прикладывает через
встроенный `plannotator_inbox`; у задачи один тред, новые редакции решения
отправляются туда же. Прогресс не требует нового вложения. Receipt в `inbox.json`
связывает тред/сообщения с редакциями и хешами, исходный MD — единственный источник
истины. Явное approval относится к редакции; реализация требует отдельного запроса.
MD и receipt исключаются из Git локально. При недоступном Inbox план сохраняется,
ошибка сообщается; альтернативный транспорт не используется. См. `references/plan-inbox.md`.
Посторонние находки — в `.ai-plans/findings.md` текущего worktree.
Если вы явно откладываете исправление/решение по находке, агент сразу отправляет
безопасное сообщение только через встроенный `plannotator_inbox`. Если инструмента
нет, сохраняет находку локально и сообщает «Inbox: не отправлено»; shell-fallback
и другие способы отправки не используются.
Подтверждение доставки сохраняется локально; при ошибке агент сообщает, что
уведомление не отправлено. К уведомлению о находке рабочие файлы не прикладываются.
Известная задача восстанавливается автоматически перед продолжением после
compaction/смены модели; выбор задачи и обзор остальных планов — по запросу.
[Описание процесса](../../docs/engineering-ai-skills-guide.md#планы-и-прогресс-в-worktree).
Установщик проверяет наличие Plannotator и при отсутствии даёт официальный GitHub;
расширения и хуки автоматически не устанавливаются.
Старые agreement-файлы автоматически не переносятся и не удаляются. Пробелы сохраняются автоматически отдельными самодостаточными карточками
в `~/ai/learning/gaps/` домашней папки, вне всех worktree. После проверки —
в `~/ai/learning/archive/`. В одной карточке без выбора режима сохраняются текстовый указатель проекта,
файла, метода и строк, а также независимо выдуманный пример с кодом и условиями.
Копировать рабочий код, diff, конфигурацию и логи запрещено; ссылки не создаются.
В указанном доступном проекте Coach исследует актуальное место; на личной машине
использует выдуманный пример, не требуя закрытые исходники.
Установщик не создаёт пустые карточки и не переносит прежние журналы: перед
удалением worktree попросите агента перенести его записи по правилам политики.

## Проверки и обновление

```bash
python3 tools/omp/tests/test_install.py
```

После `git pull` ссылки используют новые исходники. Начните новую сессию OMP.
После обновления повторите установку, чтобы подключить новые модули.
Чтобы отключить комплект, удалите только ссылки, созданные установщиком,
и при необходимости верните свою сохранённую конфигурацию.
