# Локальное состояние работы

Читать до создания/обновления рабочего MD, сохранения находки или восстановления состояния. Подробный план — [planning.md](planning.md), передача роли — [handoff.md](handoff.md).

## Размещение и Git

Рабочие планы, прогресс и находки хранить в `.ai-plans/` текущего worktree. Внешних копий планов, глобальной базы/реестра задач и фоновой синхронизации нет. Явно отложенные находки дополнительно отправлять кратким уведомлением в Inbox по [inbox.md](inbox.md); это разрешённое исключение, не копия рабочих файлов. Учебные карточки — отдельный существующий журнал, не резервная копия рабочих документов.

До первой записи определить корень worktree через Git, проверить отсутствие symlink в целевом пути и отслеживаемых файлов в `.ai-plans/`. Найденные чужие файлы/символические ссылки не перезаписывать и не удалять. При конфликте уточнить безопасное размещение.

Идемпотентно добавить `/.ai-plans/` в локальный `info/exclude` общего Git-каталога, сохранив остальные строки; проектный `.gitignore` не менять. Проверить `git check-ignore` и отсутствие плана в индексе. При невозможности исключения остановить создание MD и сообщить причину. Перед коммитом/MR повторить проверку индекса; не применять `git add -f`, не удалять чужую staged-запись автоматически.

Ограничения проекта и NDA имеют приоритет: сохранять только безопасное описание и разрешённые текстовые указатели, без рабочего кода, diff, секретов, конфигураций и логов. Если проект запрещает даже такое хранение, сообщить конфликт и использовать явно согласованный формат.

## Обновление состояния

У задачи один основной `.ai-plans/<task-id>/plan.md`. Перед записью перечитать файл; не затирать чужие изменения устаревшей копией. Один редактор на документ; несколько сессий не должны одновременно редактировать один план. При конфликте сохранить обе позиции и уточнить согласование. Для одной сессии в одном worktree дополнительная координация не требуется.

Автоматически обновлять после принятого решения, завершённого шага, проверки, найденного блокера и перед handoff/окончанием сессии. Сохранять редакцию решения и подтверждение, текущую фазу/флаги, ID шага, фактически сделанное, проверки с результатами/ограничениями, статус принятия и следующее действие. До окончания reverse explain принятие открыто; только явная отсрочка означает «reverse explain отложен». Не закрывать задачу по одним зелёным тестам.

Для точного Fast-Track полный план не обязателен. Если нужно сохранить отложенное принятие/точку возврата, создать краткую запись с целью, границами, контекстом, состоянием проверок и следующим действием, соблюдая то же исключение из Git; отдельное ревью плана не навязывать. Без причины пустые рабочие документы не создавать.

После записи проверить фактическое содержимое, сообщить путь при создании/важном обновлении. Ошибку назвать явно: «обновление не сохранено»; дельту оставить в чате. Не заявлять сохранение или подтверждение без проверки. Старые agreement-файлы можно использовать как выбранный источник прежней задачи; не переносить и не удалять их автоматически, не поддерживать две независимо редактируемые версии.

## Посторонние находки

Баги и улучшения, найденные при другой работе, автоматически записывать в `.ai-plans/findings.md` текущего worktree после точечной проверки дублей. Каждая находка: стабильный ID `F1`, симптом, разрешённый указатель места, свидетельство/степень уверенности, способ проверки, статус и связь с шагом. Подозрение не выдавать за подтверждённый дефект. Не копировать рабочие фрагменты и не начинать исправление без запроса. Если находка блокирует текущий контракт, явно пересмотреть затронутый шаг.

По просьбе показать находки читать этот файл. При выборе находки в работу связать её ID с планом и обновлять статус в исходной записи, не теряя незавершённые находки.

Когда пользователь явно решает отложить исправление/конкретное продолжение,
пометить находку «отложено», записать его решение и сразу выполнить [inbox.md](inbox.md).
Дополнительные поля записи: notification-key, Inbox-статус, thread/message ID и
URL/время фактической отправки либо причина ошибки/неопределённости. Отправка и
исправление — разные статусы. При восстановлении повторно не отправлять уже
доставленное. Обычное обнаружение бага без решения об отсрочке остаётся локальным.

## Срок жизни

Локальное состояние существует, пока существует worktree. При его удалении по поручению пользователя назвать наличие незавершённых планов/находок и неотправленных уведомлений. Доставленные уведомления остаются в Inbox, но не восстанавливают весь план. Не создавать внешнюю копию вместо решения пользователя. Удалённые документы не обещать восстановить. При смене worktree не искать планы по всем проектам и не переносить подтверждение на другую версию кода без сверки.
