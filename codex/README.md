# Codex: подключение Copilot, Coach и Executor

Этот вариант подключает общие файлы `shared/agent/` к **локальному** Codex CLI
и IDE extension. Навигацию по трём ролям и методике см. в
[общем гайде](../docs/engineering-ai-skills-guide.md).

Нужны macOS/Linux, Bash, Python 3 и отдельно установленный Codex с подключённой моделью.
В Windows используйте WSL и запускайте Codex и установщик в одной среде WSL.
Локальная установка не гарантирует доступность файлов в облачном окружении
ChatGPT или в другой машине: там свои файловая система и способы установки.

## Установка

Из корня клонированного репозитория:

```bash
bash codex/scripts/install.sh --dry-run
bash codex/scripts/install.sh
```

Сначала проверьте вывод dry-run. Установщик добавляет управляемый блок в действующий глобальный файл инструкций и создаёт ссылки:

| Где Codex ищет | На что указывает ссылка |
| --- | --- |
| `${CODEX_HOME:-~/.codex}/AGENTS.override.md` или `AGENTS.md` | управляемый блок с текстом `role-orchestration.md` и абсолютным путём к политике |
| `${CODEX_HOME:-~/.codex}/references/policy-details.md` | подробная политика для чтения по событию |
| `~/.agents/skills/coach` | общий Coach со справочниками |
| `~/.agents/skills/copilot` | общий Copilot со справочником |
| `~/.agents/skills/executor` | общий Executor со справочником |

`CODEX_HOME`, если задан, должен быть абсолютным. Параметры `--codex-home` и
`--skills-dir` позволяют явно задать абсолютные пути, например для тестов.
`--skills-dir` меняет только место установки: сам Codex не начинает искать
произвольный путь автоматически. Для обычного использования оставьте
`~/.agents/skills`. При переопределении `--codex-home` также обеспечьте запуск
Codex с тем же `CODEX_HOME`.

Расположение и механизм symlink соответствуют [документации о skills](https://learn.chatgpt.com/docs/build-skills)
и [инструкциям AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
Локальные проектные `AGENTS.md` и skills могут дополнять или уточнять глобальные
правила; инструкции пользователя и среды имеют свой приоритет.

## Существующий AGENTS.md и переустановка

Установщик выбирает действующий глобальный файл: непустой `AGENTS.override.md`,
иначе `AGENTS.md`. Существующие инструкции сохраняются, а в конец добавляется
блок между `<!-- AI-HARNESS-ROLES:BEGIN -->` и `<!-- AI-HARNESS-ROLES:END -->`.
Его контрольная сумма позволяет обнаружить ручные изменения внутри блока.
Для активных инструкций в виде символической ссылки установка останавливается:
проверьте ссылку вручную, чтобы не изменить чужой файл.

После `git pull` повторно запустите установщик. Он обновит только управляемый
блок; текст пользователя до и после него останется прежним. Если блок уже
актуален, файл не переписывается. Редактируйте собственные инструкции вне
маркеров: при ручном изменении внутри блока, отсутствующих/повторных маркерах
или неверной контрольной сумме установка останавливается и сохраняет файл.

Перед изменением существующего файла создаётся проверенная резервная копия
рядом с ним, имя содержит `.ai-harness-backup-`. При первом создании файла
резервировать нечего. `--dry-run` показывает действие без записи и резервных копий.
Файл обновляется атомарной заменой; конфликтующие файлы skills и ссылки не
перезаписываются. При ошибке откатываются новые ссылки этого запуска; пустые
созданные каталоги и резервные копии могут остаться. Если файл или override
изменился во время установки, она останавливается. Не запускайте установщик
одновременно из нескольких процессов.

При размере глобальных инструкций свыше стандартного лимита 32 KiB установщик
предупреждает: проверьте `project_doc_max_bytes` в конфигурации Codex и объём
проектных инструкций. Наличие файла само по себе не гарантирует его полную загрузку.

Если skill с тем же именем найден из другого места, Codex может показать оба
варианта. Проверьте источники в `/skills` до удаления или отключения skills.
Существующие ChatGPT skills не изменяются этим установщиком.

## Как проверить

1. Начните новую локальную сессию Codex в любом тестовом проекте.
2. Откройте `/skills` либо наберите `$` и убедитесь, что видны `coach`,
   `copilot`, `executor`. Например: `$copilot помоги исследовать задачу`.
   Если они не отображаются, проверьте путь, права чтения и конфигурацию skills.
3. Спросите: «Какие глобальные инструкции и правила выбора ролей действуют в
   текущей сессии?». Ответ — поведенческая проверка, а не доказательство того,
   что модель всегда соблюдёт все правила.
4. Проверьте в учебной задаче: `$coach` сохраняет учебный формат; `$copilot`
   исследует и задаёт вопросы; `$executor` выполняет согласованный шаг. Выявленный
   пробел сохраняется в `~/ai/learning/` при наличии файлового доступа.

Установщик проверяет ссылки и доступность файлов; он не запускает Codex, не
проверяет авторизацию, модель, фактическое обнаружение skills и поведение AI.
См. также [сценарии оценки](../evals/role-behavior.md).

## Обновление и удаление

Skills и подробная политика подключены ссылками к клону. После `git pull`
повторно запустите установщик, чтобы обновить управляемый блок `AGENTS.md`,
и начните новую сессию. Перемещение или удаление клона сломает ссылки; перед
повторной установкой проверьте старые пути вручную. Скрипт не удаляет чужие или
битые ссылки автоматически. Личные карточки `~/ai/learning/` не хранятся в
репозитории и не затрагиваются.

Чтобы удалить интеграцию, удалите только управляемый блок вместе с маркерами
из активного файла инструкций. Затем проверьте, что ссылки на политику и три
skills указывают на ваш клон, и удалите только эти четыре ссылки. Не удаляйте
пользовательские инструкции, другие skills или исходники клона.

Для разработчиков: `python3 codex/tests/test_install.py` запускает тесты в
одноразовых временных директориях и не трогает реальные настройки.
